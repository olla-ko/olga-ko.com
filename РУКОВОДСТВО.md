# Как устроен сайт olga-ko.com и как его править 

Это руководство для человека, а не для программиста. Здесь — что где лежит
и как поменять или добавить контент руками, без админки.

## Главная идея

Сайт — это набор файлов в этом репозитории. Ничего не «крутится на сервере»:
при каждой отправке изменений на GitHub (git push) робот автоматически собирает
из файлов готовые страницы и выкладывает их на olga-ko.com. Обычно это занимает
2–5 минут. Статус сборки виден во вкладке **Actions** на GitHub: зелёная галочка —
сайт обновился, красный крестик — что-то сломалось (чаще всего битая ссылка
на картинку; в логе будет написано, какая именно).

Правишь файл → коммит → пуш → через пару минут изменение на сайте. Всё.

## Карта папок

### То, что вы будете править

| Где | Что это |
|---|---|
| `content/` | **Тексты портфолио и резюме.** `portfolio-ru.md` / `portfolio-en.md` — карточки на главной портфолио; `cv-ru.md` / `cv-en.md` — резюме |
| `illustration/`, `big-library/`, `calligraphy-and-lettering/` | Простые страницы: в каждой папке `content.md` — текст страницы, рядом `img/` — её картинки |
| `src/cases/` | **Страницы-кейсы** («Взносы ИП за себя» и т.д.). Внутри HTML-разметка — аккуратнее, чем с md |
| `src/pages/home.njk` | **Разводная** — список ссылок на все разделы, лежит по адресу olga-ko.com/home.html |
| `src/pages/root-redirect.njk` | Корень olga-ko.com — сразу перекидывает на портфолио (обычно править не нужно) |
| `img/portfolio/` | Картинки и скриншоты кейсов |
| `assets/` | Аватар, иконки, PDF резюме |

### Служебное (обычно трогать не нужно)

| Где | Что это |
|---|---|
| `src/_includes/` | Шаблоны-каркасы страниц (шапка, навигация — одна на все страницы) |
| `lib/`, `styles/`, `scripts/` | Код сборки: превращение md в HTML, стили, проверка ссылок |
| `.github/workflows/` | Тот самый робот, который собирает и выкладывает сайт |
| `admin/` | Админка (веб-редактор на Railway) — отдельное приложение, сайт от неё не зависит |
| `cat-in-cap/` | **Архив старого сайта и блога — не редактируется, лежит как есть** |
| `_site/`, `node_modules/` | Создаются автоматически, в git не попадают — можно смело удалять |

## Как править контент

### Карточка портфолио

Открыть `content/portfolio-ru.md`. Каждая карточка — блок между `---`,
поля задаются «тегами» в двойных скобках:

```markdown
---

## Название кейса
<<Цвет>>
green
<<Картинка>>
../img/portfolio/06-00-payments.png
<<Картинка мобильная>>
../img/portfolio/06-00-payments-mobile.png
<<Задача>>
Одно-два предложения о задаче.
<<Решение>>
Одно-два предложения о решении.
<<Цвет кнопки>>
green
<<Текст кнопки>>
Рассказ о решении
<<Ссылка кнопки>>
payments/
---
```

Цвета карточки: `green`, `yellow`, `blue`. Цвета кнопки: `green`, `red`, `blue`.
Не забудьте продублировать карточку в `portfolio-en.md` на английском.

### Запись в резюме

`content/cv-ru.md`, тот же принцип блоков между `---`:

```markdown
---

<<Период>>
январь 2026 —
по настоящее время
<<Должность>>
Product Designer
<<Компания>>
Компания
<<Описание>>
Чем занималась и какие результаты.
```

### Простая страница (иллюстрация, библиотека…)

Открыть `content.md` в папке страницы и писать обычный Markdown:
`# Заголовок`, `## Подзаголовок`, `![Картинка](img/01.png)`, списки, ссылки.
Картинки класть в `img/` рядом с этим `content.md`.

Обычно картинка растягивается на всю ширину колонки. Если нужен точный размер,
добавьте ширину в пикселях через пробел: `![Картинка](img/01.png =600)` —
картинка будет 600px шириной (высота подстроится по пропорции, на узких экранах
она ужмётся, чтобы не вылезать за край). Скриншоты с ретины обычно ставят
вполовину их настоящей ширины: файл 1200px → `=600`.

### Страница-кейс

`src/cases/<имя>-ru.njk` (и `-en` для английской версии). Сверху — небольшая
служебная шапка (не трогать), ниже — HTML кейса: `<div class="paragraph">` —
смысловой блок, внутри `<h2>/<h3>` — заголовки, `<p>` — абзацы,
`<img src="../../img/portfolio/..." class="doubleSize">` — скриншот.
Проще всего копировать соседние блоки и менять текст.

## Как добавить новую простую страницу (3 шага)

Например, страница «Керамика» по адресу olga-ko.com/ceramics/:

1. Создать папку `ceramics/`, в ней файл `content.md` с текстом
   (и `img/` для картинок, если нужны).
2. Создать `src/pages/ceramics.njk` — скопировать `src/pages/big-library.njk`
   и поменять в нём две строки: `mdSource: "ceramics/content.md"` и
   `permalink: "/ceramics/index.html"`.
3. Добавить ссылку на разводную: в `src/pages/home.njk` скопировать любой
   `<li>…</li>` из списка и поменять адрес (`ceramics/`) и название.

После пуша страница появится на сайте и в списке файлов админки (она находит
страницы автоматически).

## Как посмотреть результат до публикации

```bash
npm install        # один раз на новом компьютере
npm run build      # собрать сайт в папку _site
npm run serve      # локальный сайт на http://localhost:8080 с автообновлением
```

## Как опубликовать

```bash
git add -A
git commit -m "Короткое описание: что поменялось"
git push
```

Через 2–5 минут — на сайте. Статус: GitHub → вкладка Actions.

## Частые вопросы

**Сломалась сборка после правки.** Почти всегда это ссылка на несуществующую
картинку — проверка ссылок нарочно останавливает публикацию. Открыть красный
прогон в Actions, в логе будет путь битой ссылки.

**Куда класть картинки?** Скриншоты кейсов — `img/portfolio/`; картинки простых
страниц — `img/` рядом с их `content.md`; иконки и PDF — `assets/`.

**А блог?** `cat-in-cap/` — законсервированный архив. Новые посты туда не
добавляются, стили и тексты не правятся.

**Админка** (редактор в браузере с предпросмотром) — см. раздел «Админка»
в [README.md](README.md). Сайт работает независимо от неё. У каждой страницы
в редакторе есть лента версий: каждое «Сохранить» добавляет версию (ничего не
затирается), любую можно открыть и опубликовать — в том числе старую, это
безопасный способ откатить неудачную правку. Ненужные черновики можно удалить
навсегда (корзинка у версии); опубликованные версии не удаляются.
