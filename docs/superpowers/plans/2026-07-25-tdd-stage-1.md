# Этап 1: тестовый фундамент и логика сохранения — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Вынести логику сохранения файла из `admin/server.js` в чистый модуль, покрыть её тестами (включая регрессии на два известных дефекта) и включить в CI гейт, который блокирует правки кода, но пропускает публикацию контента.

**Architecture:** Функциональное ядро — императивная оболочка. Правила принятия решений переезжают в `admin/lib/save.js` (чистые функции без зависимостей), `admin/server.js` остаётся транспортом: HTTP, авторизация, обращения к GitHub API. Дорогое чтение ветки `main` сохраняется ленивым: чистая функция возвращает третье состояние `need-main-sha`, по которому оболочка дочитывает недостающее и спрашивает решение повторно.

**Tech Stack:** Node 24 (локально) / Node 22 (CI), встроенный раннер `node:test`, CommonJS, GitHub Actions.

## Global Constraints

- **Ноль новых зависимостей.** Только встроенные `node:test` и `node:assert`. `package.json` не пополняется.
- **CommonJS.** `admin/` не имеет `"type": "module"` — только `require`/`module.exports`.
- **Модули в `admin/lib/` не имеют зависимостей.** Ни Octokit, ни Express, ни `fs`. Только данные на входе и решение на выходе.
- **Поведение не меняется.** Это перекладывание кода. Вывод сборки `_site` обязан совпасть с состоянием до правок.
- **Коммиты делает пользователь.** В репозитории хук блокирует `git add` / `git commit`. Там, где план говорит «точка остановки», нужно сообщить пользователю, что задача готова к коммиту, и не пытаться коммитить самому.

- [ ] **Step 4: Написать минимальную реализацию**

Создать `admin/lib/save.js`:

```js
"use strict";
// Правила сохранения файла. Чистые функции: без сети, файлов и Express —
// поэтому проверяются тестами напрямую (см. admin/test/save.test.js).

const MAIN = "main";
const DRAFTS = "drafts";

// Писать можно только в main (публикация) или drafts (черновик).
function isValidTarget(target) {
  return target === MAIN || target === DRAFTS;
}

// Оптимистичная блокировка: не затираем чужую правку молча.
// mainSha: undefined — ещё не читали; null — читали, файла на main нет.
function saveDecision({ target, clientSha, currentSha, mainSha }) {
  // сверять не с чем: файла ещё нет либо клиент не прислал базовый sha
  if (!currentSha || !clientSha) return "ok";
  // на целевой ветке ничего не менялось с момента загрузки
  if (currentSha === clientSha) return "ok";
  // публикация: расхождение с main — всегда чужая правка
  if (target !== DRAFTS) return "conflict";
  // черновик: возможен законный случай «правим опубликованное, drafts отстал» —
  // для проверки нужен sha с main, оболочка дочитает его и спросит снова
  if (mainSha === undefined) return "need-main-sha";
  return mainSha === clientSha ? "ok" : "conflict";
}

module.exports = { isValidTarget, saveDecision, MAIN, DRAFTS };
```

```js
    if (target !== MAIN && target !== DRAFTS) return res.status(400).json({ error: "Недопустимая ветка" });
    if (target === DRAFTS) await storage.ensureDraftsBranch();

      if (!(mainNow && mainNow.sha === sha)) {
```

на:

```js
    if (!isValidTarget(target)) return res.status(400).json({ error: "Недопустимая ветка" });
    if (target === DRAFTS) await storage.ensureDraftsBranch();
    const current = await storage.read(p, target);
    // Оптимистичная блокировка; правила — в admin/lib/save.js. Чтение main
    // дорогое, поэтому делаем его только когда модуль об этом просит.
    const currentSha = current ? current.sha : null;
    let decision = saveDecision({ target, clientSha: sha, currentSha });
    if (decision === "need-main-sha") {
      const mainNow = await storage.read(p, MAIN);
      decision = saveDecision({
        target, clientSha: sha, currentSha,
        mainSha: mainNow ? mainNow.sha : null,
      });
    }
    if (decision === "conflict") {
      return res.status(409).json({ error: "Версия изменилась с момента загрузки — обновите страницу и повторите" });
    }
```

### Task 3: Гейт в CI — блокируем код, пропускаем контент

**Files:**
- Modify: `.github/workflows/pages.yml` (добавить job `test`, связать с `deploy`)

**Interfaces:**
- Consumes: script `npm test` (Task 1)
- Produces: job `test`, от которого зависит `deploy`

- [ ] **Step 1: Добавить job `test` перед job `deploy`**

В `.github/workflows/pages.yml` заменить строку `jobs:` и следующую за ней строку `  deploy:` на:

```yaml
jobs:
  # Тесты гоняются на правках кода. Коммиты, меняющие только контент (их пишет
  # админка), пропускаются — публикация карточки не должна вставать из-за кода.
  test:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Определить, изменён ли только контент
        id: scope
        run: |
          BEFORE="${{ github.event.before }}"
          ZERO="0000000000000000000000000000000000000000"
          if [ "${{ github.event_name }}" != "push" ] || [ -z "$BEFORE" ] || [ "$BEFORE" = "$ZERO" ]; then
            echo "Список изменений недоступен — тесты запускаем."
            echo "content_only=false" >> "$GITHUB_OUTPUT"
            exit 0
          fi
          if ! CHANGED=$(git diff --name-only "$BEFORE" "$GITHUB_SHA" 2>/dev/null); then
            echo "Не удалось получить diff — тесты запускаем."
            echo "content_only=false" >> "$GITHUB_OUTPUT"
            exit 0
          fi
          if [ -z "$CHANGED" ]; then
            echo "Пустой diff — тесты запускаем."
            echo "content_only=false" >> "$GITHUB_OUTPUT"
            exit 0
          fi
          echo "Изменённые файлы:"; echo "$CHANGED"
          NON_CONTENT=$(echo "$CHANGED" | grep -vE '^(content/[^/]+\.md|.+/content\.md)$' || true)
          if [ -z "$NON_CONTENT" ]; then
            echo "Изменён только контент — тесты пропускаем."
            echo "content_only=true" >> "$GITHUB_OUTPUT"
          else
            echo "Изменён код — тесты запускаем."
            echo "content_only=false" >> "$GITHUB_OUTPUT"
          fi

      - name: Setup Node
        if: steps.scope.outputs.content_only != 'true'
        uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm

      - name: Install deps
        if: steps.scope.outputs.content_only != 'true'
        run: npm ci

      - name: Run tests
        if: steps.scope.outputs.content_only != 'true'
        run: npm test

  deploy:
    needs: test
```
