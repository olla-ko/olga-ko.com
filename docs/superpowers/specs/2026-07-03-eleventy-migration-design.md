# Переезд на Eleventy — дизайн (пилот + план миграции)

Дата: 2026-07-03

## Цель

Убрать шаблонизацию копипастой (23 страницы дублируют шапку/Метрику; 13 кейсов
существуют парами ru/en с идентичной разметкой) через генератор Eleventy.
Инвариант: **внешний вид не меняется** — генерируется тот же HTML с теми же
Tailwind-классами; контент запекается в HTML (бонус: SEO и мгновенный первый рендер).

## Решения

- **Генератор:** Eleventy (v3), шаблоны Nunjucks. Вход `src/`, выход `_site/`
  (в `.gitignore`).
- **Поэтапная миграция:** страница мигрирует = её HTML удаляется из статичного
  дерева и заменяется шаблоном в `src/`; всё немигрированное копируется в `_site/`
  как есть (passthrough). Никакого big-bang.
- **Пилот:** пара кейсов `portfolio-{ru,en}/payments/` — общий layout кейса +
  два контент-файла. Верификация: сгенерированный HTML сравнивается с текущим
  (нормализованный дифф), плюс браузерная проверка.
- **Контент кейсов остаётся HTML** внутри шаблонов (разметка кейсов — кастомные
  классы `.case/.paragraph/.doubleSize`; конвертация в чистый md изменила бы DOM).
  Метаданные (title, lang, путь) — во frontmatter.
- **Не мигрируем никогда:** `cat-in-cap/` (архив + блог — passthrough), `img/`,
  `assets/`, `content/`, PDF и пр.
- **CI:** в workflow добавляется шаг `eleventy`; линк-чекер гоняется по `_site/`;
  в артефакт Pages едет `_site/` (служебные файлы репо перестают попадать в прод;
  `.nojekyll` в артефакте не нужен, но безвреден).
- **URL не меняются:** permalink каждого шаблона повторяет текущий путь
  (`/portfolio-ru/payments/` и т.д.).

## Порядок миграции (после одобрения пилота)

1. Остальные 11 пар кейсов (те же layout).
2. Лендинги `portfolio-{ru,en}/index.html` (общий layout, разница — язык/контент).
3. Разводная и markdown-страницы.
4. Финал: единый head-partial (Метрика/шрифты/favicon в одном месте).

## Верификация (каждый этап)

- Дифф сгенерированного HTML против текущего (нормализация пробелов).
- Браузер: computed styles / скриншоты, работа scriptCase.js.
- `scripts/check_links.py` по `_site/`.
